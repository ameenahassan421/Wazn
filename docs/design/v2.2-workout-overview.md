# Handoff: Wazn Design v2.2 — the workout overview

## Overview

Extends **v2 "Loaded Ink, refined"** and **v2.1** with the one screen the
system has never had and the app most needs: the **whole-workout view**.

This is the structural phase (parity plan §3-U2, release R2). Every token,
radius, elevation rule, motion rule and voice rule from v2 applies unchanged.
No new colour, no new typeface, no new texture. `v2.2-workout-overview.html`
opens directly in a browser; it is a reference to recreate in the codebase,
not production code.

**Design pass only. No app code is part of this deliverable.**

## The problem, stated exactly

Hevy's active workout is a table: every exercise visible, planned rows
pre-filled, a checkmark per row. Wazn is sequential — one exercise per screen,
a "Log set" button that _creates_ a row, and a dashed "Next" card standing in
for the rest of the session.

The cause is a rule that is **correct and stays**: sets are never
pre-inserted, because _a set row means it happened_
(`LogScreen.tsx:337`, DECISIONS.md 2026-08-01). Pre-inserting planned sets
would put lifts in History that were never performed, and History is what
every chart is built from.

The rule was allowed to dictate the interface. It should only dictate the
database. **v2.2 separates them**: planned rows are rendered client-side and
become a real `INSERT` at the moment of commit. Hevy's ergonomics on top of
Wazn's data honesty.

## The two-level model, and why the focused view survives

The single biggest risk in this phase is regressing the core loop to gain a
table. Today's focused view is not a weakness — it is an appliance: a 30px
input, ± steppers at the plate increment, plate calculator, warm-up ramp,
mid-set unit flip that converts the draft. Cramming that into a table cell
would be a parity win and a product loss, and the protect list (parity plan
§1) forbids it.

So the two levels have different jobs, and the split is the whole design:

|            | **Overview** — the spine             | **Focused** — the zoom               |
| ---------- | ------------------------------------ | ------------------------------------ |
| Answers    | "Where am I in this session?"        | "What exactly am I about to lift?"   |
| Shows      | Every block, every row, what's done  | One exercise, full instrumentation   |
| Input      | **None.** Values are read, not typed | Keyboard, steppers, plate calc, ramp |
| Commit     | One tap on the row's check           | Existing commit button               |
| Reached by | Default on Start workout             | Tapping a row's **values**           |

**One row, two targets, two intents:**

- Tap the **check** → commit the row exactly as shown. This is the modal case
  and it costs **1 tap**.
- Tap the **values** → open the focused view for that exercise, pre-scrolled
  to that row. This is the "not what I planned" case.

The 1-tap repeat-set cost is therefore unchanged from today, which GATE U2
requires and the protect list demands. Nothing else on the protect list is
touched: superset round-rest, the deadline timer, the unit-flip conversion and
PR-on-insert all live below this screen, not in it.

## Where planned rows come from

A **ghost row** is client state. It has never been in the database and is not
in it now.

Precedence, resolved per exercise:

1. **Routine active** — the routine gives the row _count_ and the _rep_
   target; the previous session for that exercise gives the _weight_, because
   a routine stores what to do and only history knows what you lifted.
2. **No routine (freestyle)** — the previous session gives count and values,
   exactly what the current draft-seeding already does
   (`SetEntry.tsx:102-109`).
3. **Neither** — one empty ghost, values blank. Tapping its values opens the
   focused view, where typing is a first-class act rather than an apology.

Warm-up rows are ghosted from the ramp when the ramp is enabled for that
exercise, and carry the existing warm-up set type so they stay out of PRs and
charts.

## Row states — the ladder

Four states, distinguished by **value contrast, border style and fill**, never
by hue alone. One accent, no red, per §2.4.

| State                                       | Values                     | Ring                           | Check target                           |
| ------------------------------------------- | -------------------------- | ------------------------------ | -------------------------------------- |
| **Ghost** (planned, not done)               | `--color-muted`            | 1px **dashed** hairline        | Outline square, `--color-line`         |
| **Committed** (it happened)                 | `--color-text`, full chalk | 1px solid hairline + top light | **Filled amber**, ink glyph            |
| **Committed + PR**                          | full chalk                 | solid hairline                 | filled amber + existing knurl PR badge |
| **Editing** (focused view open on this row) | full chalk                 | 1px solid **amber**            | outline amber                          |

Dashed already means "not yet real" in this system — v2.1 gave the routine
builder a dashed-amber card for exactly that reason. v2.2 reuses the meaning
rather than inventing one.

Ghost → committed is the existing 90ms `set-commit` rise
(`--motion-instant`, "did my set save?"). No new motion token.

## Row anatomy

Row height **56px** — the ghost-row commit target minimum, and the hot-path
size from §2.4. At 390px with 18px page padding, 354px of usable width:

```
 ├─28px─┤├──────────── 270px, one tap target ────────────┤├──56px──┤
 ┌──────┬───────────────────────────────────────────────┬─────────┐
 │  3   │  102.5 × 8                        ↺ 100 × 8   │    ✓    │  56px
 └──────┴───────────────────────────────────────────────┴─────────┘
   index          value 24/500 tnum        previous          commit
   mono 11        (--text-figure)          mono 11
   muted                                   muted
```

- **Index** — mono 11, muted. Working sets number from 1; warm-ups carry the
  existing letter treatment rather than stealing a number.
- **Value** — `--text-figure` (24/500, tabular). 24px satisfies §2.4's
  numeric floor with 16px of breathing room in a 56px row; **the 20px
  multi-set exception is not needed and is not claimed.**
- **Previous** — mono 11, muted, trailing, aligned to the check's inline edge.
  Shown only where a previous set exists. This is the retention engine: seeing
  last time on every row is what turns a session into a game against yourself,
  and it costs one query the app already makes.
  On a **committed** row it becomes the comparison: `▲ +2.5` in amber when
  beaten, `→` in `--color-muted` when matched. Never red when down — a lighter
  day is not a failure, and §2.4 has no red.
- **Check** — 56×56, inline-**end**. Closest to the thumb in a one-hand grip,
  and it mirrors correctly in RTL because it is a logical edge.

The value and previous share **one** tap target spanning between index and
check: ~270×56px. A target that size cannot be missed with chalk on your
hands.

## Exercise block

```
┌─────────────────────────────────────────────────────────┐
│ ▤   Bench Press (Barbell)                            ⋮  │  header, 52px
│     3 / 4 · seat position 4                             │  meta line
├─────────────────────────────────────────────────────────┤
│  1   102.5 × 8                    ↺ 100 × 8         ✓   │  committed
│  2   102.5 × 8                    ↺ 100 × 8         ✓   │  committed
│  3   102.5 × 8                    ↺ 100 × 8         ✓   │  committed
│  4   102.5 × 8                    ↺ 100 × 8         ☐   │  ghost
└─────────────────────────────────────────────────────────┘
```

- **Grip** (`▤`) — an explicit 44×52 drag handle at the header's inline-start.
  Reorder starts here and nowhere else, so a drag anywhere in the block still
  scrolls. See _Reordering_.
- **Name** — `--text-title` (19/600), one line, truncating. **It gets the whole
  header row**, and that is a correction the first render forced: with the
  progress count and `⋮` sharing the line, "Bench Press (Barbell)" and "Lat
  Pulldown (Cable)" both truncated — the two most common lifts in this app,
  unreadable at a glance. The header is the block's identity and identity does
  not share a line.
- **Meta line** — `3 / 4 · seat position 4`. Progress in mono 11 muted
  (committed over planned, the only number that answers "am I done here"), then
  the note: 13px muted, from the existing `exercise_notes` (migration 0008,
  unread since the day it landed). The line always exists because progress
  always exists, so block height does not jump between exercises that have a
  note and exercises that do not. When the block is complete the count turns
  amber — the only state change it has.
- **`⋮`** — 48×52: add/edit note, per-lift rest, un-superset, remove exercise.
  Everything that is not logging.

## Superset rails

Supersetted blocks render **adjacent** and are joined by a **2px solid amber
rail** on the inline-start edge, spanning from the first block's header to the
last block's final row.

Not knurl. §2.4 reserves knurl for thin bands and the PR badge; a rail is
structure, not texture.

The existing semantics are untouched below the glass: alternation still picks
whoever has the fewest sets logged, and rest is still one timer per **round**,
not per set (`supersets.ts:52-86`). The rail is how that becomes visible for
the first time — today it is correct and invisible.

## Reordering

Long-press the grip (250ms), then drag. The block lifts to `--color-raised`
with the hairline ring, and neighbours part to show the drop target. Release
commits.

- **Hand-rolled pointer events first.** `@dnd-kit/core` (~10 KiB) only if the
  hand-rolled version fights scroll, and only with a DECISIONS.md entry
  naming the size — the precache ceiling is 600 KiB and currently sits at 571.
- **Order must survive a reload.** A reordering that a lock screen forgets is
  worse than none, and the trust ladder (heuristics §4) starts with
  "in-progress workout persists". Where that order lives is U2b's call.
  **One warning for whoever implements it: do not name the column
  `position`.** It is a reserved word, and migration 0007 shipped with one and
  failed to parse in its entirety.
- Reordering is for **blocks only**. Individual sets do not reorder — set
  order is chronological fact, not preference.

## Skipped exercises

Mid-workout there is no such thing as skipped; there is only not-yet-done, and
implying otherwise would be the app scolding a lifter who is still lifting
(heuristics §5: never guilt).

Skipped exists at exactly one moment: **Finish**. A block with zero committed
sets is listed on the finish summary under a muted `SKIPPED` micro tag, named
but not scored. The workout still saves. Routine adherence becomes visible for
the first time without ever becoming a lecture.

The existing armed-finish row is where this surfaces, and it is allowed to
prompt because Finish is not mid-set — §2.1 protects the logging flow, and
this is the end of it.

## Rest timer coexistence

The timer bar stays where it is: sticky, full width, 56px, directly above the
tab bar. It never becomes a modal and never covers a row.

- The scroll container carries bottom padding equal to **timer bar + tab bar**
  (~118px) so the final row is always reachable above the chrome.
- **On commit, the overview scrolls the next actionable ghost into the thumb
  band** — not to the top of the screen. The next thing you will touch should
  arrive under the thumb that just committed.
- When no timer is running the padding is tab-bar only, and the layout does
  not jump: the timer bar animates in over `--motion-transition` (160ms),
  which is the token that already means "where did I come from".

## Thumb zone

390×844, chrome at the bottom ~118px. The commit band is **y 500–780**.

- Commit targets live in the bottom half by construction, because the
  auto-scroll on commit puts the next ghost there.
- The header, block names and progress counts are above the midline: read-only
  territory, per the one law.
- Nothing destructive shares an edge with a check. Remove-exercise lives
  behind `⋮`, two taps from anything that logs.

## States

**Empty — no routine, no history.** Start workout → the picker, unchanged.
After the first exercise is added, its block shows one blank ghost.
Copy: "Tap the numbers to enter your first set." Never fake data, never a
pre-filled weight the app invented.

**Empty — routine, no history for an exercise.** Ghost rows exist with the
routine's rep target and a blank weight. The blank is honest: the app knows
how many and how hard, not how heavy.

**Mid-workout.** The default. Committed rows above, ghosts below, the block
you are on scrolled to the thumb band.

**All planned rows committed.** No celebration, no modal — §2.1. The block
header's `4 / 4` is the whole signal. A muted "Add set" row appears at the
block's end, because working past the plan is normal and should cost one tap.

**Offline.** U3's problem, not U2's, but the overview must not lie in the
meantime: a committed row that has not reached the server yet renders
committed. It happened — the user did it. Reconciliation is U3's trust ladder,
and this screen is designed so that optimistic commit is a drop-in when it
lands.

**Reduced motion.** All four tokens collapse to 0.01ms, as v2 already
specifies. The commit rise becomes an instant state change; the reorder lift
becomes an instant swap. Nothing here depends on motion to be legible.

**Long names.** Truncate at one line with an ellipsis. Full name in the
focused view.

**Many sets (10+).** Nothing special. Rows are 56px and the block scrolls with
the page; there is no inner scroll container, because a scroll inside a scroll
is a rage moment with one hand.

## RTL

Logical properties throughout, so the whole screen is a flip and not a
rewrite: the grip and superset rail sit at `inline-start`, the check at
`inline-end`, and both mirror automatically.

Figures stay Latin tabular digits in isolated `dir="ltr"` spans, per v2 §RTL —
`102.5 × 8` reads identically to a lifter in Cairo and one in Minnesota.

The `↺` previous glyph is directional and **does** flip in RTL, unlike the
clock and trend icons (v2 iconography rule).

## What this design does NOT do

Named so the build does not drift into them:

- **No inline keyboard in the overview.** Typing happens in the focused view,
  where the instrumentation lives. A 24px number in a 56px row is for reading.
- **No per-cell editing.** One tap target per row, not three.
- **No "complete all" button.** It would let someone log a workout they did
  not do, which is the same lie as pre-inserted sets wearing a different hat.
- **No pre-inserted sets. Ever.** Ghosts are client state until the check is
  pressed.
- **No set reordering** — only blocks.
- **No new colour, texture or motion token.** Everything above is v2 parts.

## GATE U2 (from the parity plan, unchanged)

Ameen logs a full upper/lower session in overview mode in a real gym; repeat-set
commit is ≤ today's tap count (1 tap); a pocketed-phone set can be back-filled
in ≤3 taps; supersets and the protect-list behaviours all survive. Beta
testers' first-workout completion rate does not drop.

Two of those are answered by this design on paper and must still be proven in
a gym: repeat-set commit is **1 tap** (the check), and a pocketed set is **1
tap** if the ghost matches what you did, **3** if it does not (values → edit →
commit).

## The renders are part of the deliverable

`v2.2-workout-overview.html` was rendered and looked at, not just written —
§4's screenshot rule applies to a design handoff at least as much as to the
app, and it earned its place twice here:

1. **Exercise names truncated.** "Bench Press (Ba…", "Lat Pulldown (C…". The
   header anatomy changed because of it (above).
2. **The PR badge was unreadable** — knurl drawn straight under 10px letters.
   It now matches the app's `tag-pr`: dark ink on an amber field with the
   texture behind it. **Texture must never be asked to carry legibility.**

The file also self-hosts IBM Plex from `public/fonts/` rather than trusting
the Google Fonts CDN the v2.1 handoff links. A reference that silently falls
back to the system sans is a reference to a different design — the fallback is
wider, and the first render of this file truncated names that fit fine in
Plex. It now renders correctly with no network at all.
