Wazn · Design v2.2 — the workout overview

The structural phase. Hevy's active workout is a table; Wazn's is a corridor — one exercise per screen, a button that creates a row. The cause is a rule that is correct and stays: sets are never pre-inserted, because a set row means it happened. v2.2 stops that rule from dictating the interface. Planned rows are rendered client-side and become a real INSERT at the moment of commit. Every token, radius, motion and voice rule from v2 applies unchanged — no new colour, no new texture, no new motion token.

01

The overview — mid-workout

The spine of the session. Every block visible, every planned row rendered, committed rows visibly distinct from ghosts. This screen's job is the ledger, not the keyboard — values are read here and typed in the focused view, which survives unchanged as the zoom state.

One row, two targets

Tap the check → commit exactly as shown. The modal case, 1 tap, unchanged from today and required by GATE U2. Tap the values → open the focused view at that row, where the 30px input, ± steppers, plate calculator and warm-up ramp live. A table cell would have regressed all four; the protect list forbids that.

Row: 56px, four regions

28px index (mono 11) · ~270px one tap target holding value and previous · 56px check at inline-end, nearest the thumb and correct in RTL by construction.

Values are 24px

--text-figure (24/500 tabular) satisfies §2.4's numeric floor with 16px of room inside a 56px row. The 20px multi-set exception is not needed and is not claimed.

The previous ghost is the retention engine

Mono 11, muted, trailing. Seeing last time on every row turns a session into a game against yourself, and it costs a query the app already makes. On a committed row it becomes the comparison — ▲ +2.5 in amber when beaten, → muted when matched. Never red when down: a lighter day is not a failure, and §2.4 has no red.

Block header

Grip (44×56, the only place a drag starts) · name 19/600 truncating to one line · 3 / 4 committed-over-planned, the only number that answers "am I done here" · ⋮ for everything that is not logging. The note line is the second half of O9, read from exercise_notes — a table that has existed since migration 0008 and been read by nothing.

Timer coexistence

Sticky, 56px, above the tab bar, never a modal, never covering a row. The scroll container carries ~118px of bottom padding. On commit the overview scrolls the next ghost into the thumb band — the next thing you touch arrives under the thumb that just committed.

Ghost

Values --n5, ring 1px dashed, check an outline square. Client state only — it has never been in the database and is not in it now.

Committed

Values full chalk, ring solid hairline + inset top light, check filled amber with the ink glyph. The transition is the existing 90ms set-commit rise (--motion-instant, "did my set save?"). No new motion token.

Editing

1px solid amber ring. The only amber border on the screen, so the row you are typing into is findable without reading anything.

Where ghosts come from

Routine active — the routine gives row count and rep target; the previous session gives the weight, because a routine stores what to do and only history knows what you lifted. Freestyle — previous session gives both, which is what draft-seeding already does. Neither — one blank ghost; — × 8 is honest, an invented weight would not be.

Beyond the plan

When every planned row is committed there is no celebration and no modal (§2.1). The header's 4 / 4 is the whole signal, and a muted "Add set" appears — working past the plan is normal and should cost one tap.

No "complete all" button. It would let someone log a workout they did not do — the same lie as pre-inserted sets wearing a different hat.

Superset rails and reordering

Wazn's superset semantics are already better than Hevy's default — alternation picks whoever has the fewest sets logged, and rest is one timer per round rather than per set. Today that is correct and completely invisible. The rail is how it becomes visible.

The rail

2px solid amber on the inline-start edge, spanning from the first block's header to the last block's final row. Not knurl — §2.4 reserves knurl for thin bands and the PR badge. A rail is structure, not texture.

Nothing below the glass changes

Alternation, round-rest and the group id on workout_sets.superset_group are untouched. The rail is presentation of behaviour that already exists and has never been drawn.

Reorder: grip only

Long-press the grip (250ms), then drag. Because the handle is explicit, a drag anywhere else in the block still scrolls — which is the failure mode that makes hand-rolled reordering feel broken. Hand-rolled pointer events first; @dnd-kit/core (~10 KiB) only if it fights scroll, and only with a DECISIONS.md entry naming the size. Precache ceiling is 600 KiB and currently sits at 571.

Order must survive a reload. A reordering a lock screen forgets is worse than none — the trust ladder starts with "in-progress workout persists". Where it lives is U2b's call.

One warning for whoever implements it: do not name the column position. It is a reserved word, and migration 0007 shipped with one and failed to parse in its entirety.

Blocks reorder, sets do not

Set order is chronological fact, not preference.

04

Finish — where "skipped" is allowed to exist

Mid-workout there is no such thing as a skipped exercise; there is only not-yet-done. Implying otherwise would be the app scolding a lifter who is still lifting. Skipped exists at exactly one moment — Finish — where routine adherence becomes visible without becoming a lecture.

Named, not scored

A block with zero committed sets is listed under "Not done today" with a muted SKIPPED tag. No count, no percentage, no streak consequence. The workout still saves. Never guilt.

Why a prompt is allowed here

§2.1 protects the logging flow. Finish is the end of it, not the middle, so the routine-update question ("update Upper A with today's changes?") is permitted here and nowhere else. It rides the existing armed finish row.

States not drawn here

Offline — U3's problem, but the overview must not lie meanwhile: a committed row that has not reached the server renders committed, because it happened. The screen is shaped so optimistic commit is a drop-in when U3 lands. Reduced motion — all four tokens collapse to 0.01ms; the commit rise becomes an instant state change and the reorder lift an instant swap. Nothing here needs motion to be legible. Long names truncate to one line. 10+ sets get no inner scroll container — a scroll inside a scroll is a rage moment with one hand.

RTL

Logical properties throughout, so this is a flip and not a rewrite. Grip and rail at inline-start, check at inline-end. Figures stay Latin tabular digits in isolated dir="ltr" spans. The ↺ previous glyph is directional and does flip; the clock and trend icons do not.
